How each step is laid out

Each of the seven steps has the same parts:

  • Do. The tasks, in order.

  • Example. What the step produces for User Notices.

  • Done when. What must be true before the next step.

  • Watch for. The problems that come up most often at that step.

Some steps also have blocks with the same labels as the guide, so one workbook serves new and experienced developers:

  • Basics. Plain definitions of the terms a section uses, placed before the section uses them. Read these first if the terms are new; skip them if not.

  • Going deeper. Detail for reviewers and experienced developers, with a table and the default to use.

  • Scenario. A situation, the choice or the commands, and the reason. In this workbook each scenario shows the assistant's body, the checks it fails, and the fixed code.

The process at a glance

Steps 1 to 4 repeat for each function: you write its signature and comment, the assistant writes its body, you review the body against its comment and against the security checklist, and you write its unit tests. Steps 5 to 7 run once for the whole backend: wire the stub into the running service, call every endpoint, and trace a failure.

A body that fails either part of the review goes back to the assistant, or the comment changes first and the body is reviewed again. Only a body that passes both parts gets its tests.

StepOwnerProduces
1. Template functionsDeveloperOne empty function per operation, with the signature from the interface
2. CommentsDeveloperA comment in each function: what it does, what it depends on, what it raises, what it must not do
3. BodiesAssistant writes, developer reviewsBodies that match their comments and pass the security checklist, and one change log entry per body
4. Unit testsDeveloperOne test per rule in the comment, passing
5. Stub data layerDeveloperIn-memory stores behind the store interfaces, wired into the service
6. Run itDeveloperEvery endpoint called once, with the result recorded
7. Debug by referenceDeveloperOne failure traced to its cause with a breakpoint, fixed, and covered by a test

The unit tests in Step 4 need a store to run against, so write each area's in-memory store class when you write that area's skeleton. It is a few lines per method. Step 5 then wires the stores into the running service.

Step 1. Template functions

Create one empty function for every operation the backend performs, in the folder that owns it, with the exact signature from the Stage 4 interface.

Do

  1. List the operations. Go through the Stage 1 screens one at a time. For each, write what the user does and what the backend must do in response. Add the operations no screen shows but every request needs, such as checking the session and the staff member's role.

  2. Assign each operation to a folder. A request is received by a router function and the work is done by a service function. Sign-in and session checks go in auth/. Anything that talks to an outside service gets its own service file.

  3. Copy the signature. Take the name, inputs and return type from the interface. If the interface does not have the function, add it to the interface first, then to the skeleton. Functions with no interface, such as those in app/auth/, take their signatures from the table below.

  4. Leave the body empty. Write ... as the body. Python accepts it, so the files import and the tests can call the functions. Code that runs when a file is imported and calls one of these functions, such as the seed data in app/db/stores.py (Step 5), waits until that function has its body; the order of work puts the seed last.

# app/interfaces/users.py
from typing import Protocol
from pydantic import BaseModel, ConfigDict, Field, field_validator
from app.interfaces.auth import Staff

MAX_PAGE_SIZE = 200  # the most users one GET /v1/users call returns


class User(BaseModel):
    id: int
    name: str
    phone: str     # international format, for example +15555550101
    group_id: int
    opted_in: bool


class UserSummary(BaseModel):
    """One row of the Users list."""
    id: int
    name: str
    group_id: int
    opted_in: bool


class UserGroup(BaseModel):
    id: int
    name: str


class UserUpdate(BaseModel):
    """The fields a staff member may change. Any may be left out; none may be null.
    A request with any other field, such as group_id, is rejected with 422."""
    model_config = ConfigDict(extra="forbid")

    name: str | None = Field(default=None, min_length=1)
    phone: str | None = None
    opted_in: bool | None = None

    @field_validator("name", "phone", "opted_in", mode="before")
    @classmethod
    def not_null(cls, value):
        if value is None:
            raise ValueError("may be left out, but not set to null")
        return value


class UserService(Protocol):
    async def list_users(self, group_id: int | None = None, limit: int = 50,
                         offset: int = 0) -> list[UserSummary]: ...
    async def list_groups(self) -> list[UserGroup]: ...
    async def get_user(self, user_id: int) -> User: ...
    async def update_user(self, user_id: int, changes: UserUpdate, staff: Staff) -> User: ...


class UserStore(Protocol):
    async def list_users(self, group_id: int | None, limit: int, offset: int) -> list[UserSummary]: ...
    async def list_groups(self) -> list[UserGroup]: ...
    async def get_user(self, user_id: int) -> User | None: ...
    async def save_user(self, user: User) -> User: ...

Done when

Watch for

  • List the operations that no screen shows, such as session and role checks and outbound messages, now. Otherwise Step 6 finds them missing.

  • Signatures typed from memory drift from the interface. Copy them from the interface file; a one-word difference, such as group instead of group_id, breaks the callers.

  • A function whose description needs "and" is two functions. Split it, so each half gets its own comment and its own tests.

  • A fixed path such as /v1/users/groups must be declared before /v1/users/{id} in the router. Declared after it, "groups" is read as a user id and the call returns 422.

Step 2. Comments

Write a comment inside each function that states what it does, what it depends on, what it raises and what it must not do. The assistant writes the body from this comment, you review the body against it in Step 3, and you write the tests from it in Step 4.

Do

  1. Write the five parts. Use the template below. Leave out a part only when it has nothing to say.

  2. Take the rules from the requirements. Validation rules, limits and status values come from Stage 1 and the interfaces. A rule you decide now (such as a phone number format) goes in the comment, where the reviewer and the tests can see it.

  3. Name every dependency. Anything the function uses that is not an argument: an injected store, the current user, another function it calls. A function never creates its own store or connection.

  4. Say what it must not do. Name the behavior a reader might expect from this function but that belongs to another one.

Done when

Watch for

  • A comment that repeats the function name, such as "Update the user", leaves every rule to the assistant.

  • A comment that describes the steps ("loop over the users and call send") fixes how the code is written and leaves out the rules. Describe the result and the rules; the assistant writes the steps.

  • A rule found later, in review or in testing, goes into the comment first, then the body, then a test. The comment stays the record of what the function must do.

Step 3. Bodies and review

Give the assistant one skeleton file at a time with fixed instructions, then read every body against its comment and against the security checklist before any of it runs. Each body ends in one of three outcomes: accepted, sent back, or accepted after the comment is changed first.

Do

  1. Send one file. Include the interface it implements and the store interface, so the assistant knows which store methods exist.

  2. Use the same instructions every time. The prompt below sets the rules. Keep it in the repository so every developer sends the same one.

  3. Review each body. Go through both parts of the review checklist in Going deeper: Reviewing code for security: part 1 with the comment and the body side by side, then part 2 for security. Review every body this way, whoever wrote it.

  4. Decide. A body that passes both parts is accepted. A body that does less than the comment is sent back with the missing line named. A body that does more is cut back, unless you want the extra behavior; then it goes into the comment first, and the body is accepted against the new comment. A body that fails a security check is fixed before it runs, even when it matches its comment; if the comment allowed the problem, the comment changes first.

  5. Run the interface check. tests/test_contracts.py fails if a function was added, dropped or had its signature changed. It runs with pytest, which the Stage 4 lock file installed.

  6. Check new packages and the change log. A package that a body imports for the first time goes through check 8 before anything is installed. Then check that there is one change log entry per body, in ai-change-log.md at the repository root.

  7. Open a pull request. Each area reaches main through a pull request. The reviewer goes through the same checklist; with one developer, you review your own pull request with it (Working in Git).

Basics: Security terms

  • Authentication. Checking who the caller is, for example by the session cookie issued at sign-in.

  • Authorization. Checking what that caller may do, and to which record.

  • Injection. Input that ends up executed as part of a query or a command.

  • Dependency. A library the code installs. It is a supply chain risk when it is outdated, has been tampered with, or is not the package that was intended.

  • Cross-site scripting (XSS). Text that a user entered is shown on a page as code, and runs in other users' browsers.

  • Static analysis. A tool reads the code without running it and reports risky patterns.

  • OWASP. The Open Worldwide Application Security Project, which publishes the risk lists and cheat sheets cited below.

Going deeper: Reviewing code for security

Review every body for security as well as against its comment, whoever wrote it. Generated code needs the same review as a colleague's code; it is not a way around review, testing or static analysis (Source 60). A second developer reviews each pull request with the same list before it merges (Working in Git). Automated tools run in CI (Stage 9): they find known patterns and vulnerable packages. The reviewer checks what the tools cannot know, such as who may do what to which record.

# tests/test_contracts.py
# Fails if a service class adds, drops or changes a function from its interface.
import inspect
from app.interfaces.notices import NoticeService
from app.interfaces.users import UserService
from app.services.notices import Notices
from app.services.users import Users

def differences(interface, service):
    wanted = {n: f for n, f in vars(interface).items() if inspect.isfunction(f) and not n.startswith("_")}
    built = {n: f for n, f in vars(service).items() if inspect.isfunction(f) and not n.startswith("_")}
    found = [f"{n}: missing" for n in wanted.keys() - built.keys()]
    found += [f"{n}: not in the interface" for n in built.keys() - wanted.keys()]
    found += [f"{n}: signature changed" for n in wanted.keys() & built.keys()
              if inspect.signature(wanted[n]) != inspect.signature(built[n])]
    return found

def test_notices_matches_its_interface():
    assert differences(NoticeService, Notices) == []

def test_users_matches_its_interface():
    assert differences(UserService, Users) == []

# app/services/phones.py
import phonenumbers


def format_phone(raw: str) -> str:
    # Return the number in international (E.164) form, for example +15555550101.
    # Accepts spaces, dots, hyphens and brackets; the number must start with +.
    # Depends on: the phonenumbers library.
    # Raises ValueError for text that is not a possible phone number.
    try:
        number = phonenumbers.parse(raw, None)
    except phonenumbers.NumberParseException as e:
        raise ValueError("Phone number must be in international format, starting with +") from e
    if not phonenumbers.is_possible_number(number):
        raise ValueError("Phone number has the wrong number of digits")
    return phonenumbers.format_number(number, phonenumbers.PhoneNumberFormat.E164)

is_possible_number checks the number of digits for the country. is_valid_number also checks the number against the country's assigned ranges, and rejects the 555 numbers used in this example's test data.

class InMemoryStaffStore:
    def __init__(self, staff: list[StaffRecord] | None = None):
        self.by_email = {s.email: s for s in staff or []}

    async def find_by_email(self, email: str) -> StaffRecord | None:
        return self.by_email.get(email)

    async def get_staff(self, staff_id: int) -> Staff | None:
        for record in self.by_email.values():

class InMemoryUserStore:
    def __init__(self, users: list[User] | None = None, groups: list[UserGroup] | None = None):
        self.users = {u.id: u for u in users or []}
        self.groups = list(groups or [])

    async def list_users(self, group_id: int | None, limit: int, offset: int) -> list[UserSummary]:
        rows = [u for u in sorted(self.users.values(), key=lambda u: u.id)
                if group_id is None or u.group_id == group_id]
        return [UserSummary(id=u.id, name=u.name, group_id=u.group_id, opted_in=u.opted_in)
                for u in rows[offset:offset + limit]]

    async def list_groups(self) -> list[UserGroup]:
        return sorted(self.groups, key=lambda g: g.name)

    async def get_user(self, user_id: int) -> User | None:
        return self.users.get(user_id)

    async def save_user(self, user: User) -> User:
        self.users[user.id] = user
        return user

        self.messages: list[tuple[int, int, str, str | None]] = []  # one per message sent or failed

    async def group_exists(self, group_id: int) -> bool:
        return group_id in self.group_ids

    async def add_notice(self, text: str, group_id: int, send_at: datetime,
                         author_id: int) -> NoticeSummary:
        notice = NoticeSummary(id=len(self.notices) + 1, text=text,
                               send_at=send_at, status="scheduled")
        self.notices[notice.id] = notice
        self.group_of[notice.id] = group_id
        self.author_of[notice.id] = author_id
        return notice

    async def get_notice(self, notice_id: int) -> NoticeSummary | None:
        return self.notices.get(notice_id)

    async def list_notices(self, limit: int) -> list[NoticeSummary]:
        latest_first = sorted(self.notices.values(), key=lambda n: n.send_at, reverse=True)
        return latest_first[:limit]

    async def set_status(self, notice_id: int, status: str) -> None:
        self.notices[notice_id] = self.notices[notice_id].model_copy(update={"status": status})

    async def list_recipients(self, notice_id: int) -> list[Recipient]:
        group_id = self.group_of[notice_id]
        return [Recipient(user_id=u.id, phone=u.phone)
                for u in sorted(self.users.users.values(), key=lambda u: u.id)
                if u.group_id == group_id and u.opted_in]

    async def record_message(self, notice_id: int, user_id: int, status: str,
                             provider_message_id: str | None) -> None:
        self.messages.append((notice_id, user_id, status, provider_message_id))


class FakeSmsClient:
    """Implements SmsClient without sending anything, so no message reaches a real phone."""

    def __init__(self, failing: set[str] | None = None):
        self.sent: list[tuple[str, str]] = []  # (phone, text) per message accepted
        self.failing = failing or set()        # numbers the fake provider rejects

    async def send(self, phone: str, text: str) -> str:
        # Record the message and return a fake provider message id, or raise
        # SmsError for a number in self.failing. Never calls the SMS provider.
        if phone in self.failing:
            raise SmsError("rejected by the fake provider")
        self.sent.append((phone, text))
        return f"fake-{len(self.sent)}"

Step 7. Debug by reference

When a call fails, run three checks in a fixed order: is the service running, which file does main.py name for the behavior, and what values does a breakpoint in that file show. Reproduce the failure in a unit test, then fix the comment and the body.

Do

  1. Check the service is running. The terminal shows "Application startup complete" and /docs loads. If not, the last lines in the terminal name the file and line of the startup error. A stopped service makes every call fail, and this check takes seconds.

  2. Find the file through main.py. Read the comment above the area's router, open that router, find the endpoint, and note the service function it calls.

  3. Reproduce the failure as a unit test. Call the service function with the values from the failing request. The test fails now and passes after the fix, so the bug cannot come back unnoticed.

  4. Set a breakpoint and repeat. Put it on the line after the value you doubt is set. Run the test, or repeat the call from /docs with the service running under the debugger.

  5. Read the values, then trace back. The variables view shows what each name holds; the call stack shows each call that led there. A value that is empty or different from what you expect was either never set or never sent. Follow it back up the stack.

  6. Fix in order. The comment first if a rule was missing, then the body, then run the suite. Add a change log entry for the fix.

import hashlib
import hmac
import secrets

ITERATIONS = 600_000


def hash_password(password: str, salt: str | None = None) -> str:
    # Return "salt$hash" for a password, using PBKDF2-SHA256.
    # Makes a new random salt when salt is None.
    salt = salt or secrets.token_hex(16)
    digest = hashlib.pbkdf2_hmac("sha256", password.encode(), salt.encode(), ITERATIONS)
    return f"{salt}${digest.hex()}"


def check_password(password: str, stored: str) -> bool:
    # Return True if password matches a "salt$hash" value from hash_password.
    # Compares in constant time.
    salt = stored.split("$", 1)[0]
    return hmac.compare_digest(hash_password(password, salt), stored)

    # Checks the password against a placeholder hash when the email is unknown,
    # so the response time does not show which accounts exist.
    # Logs each failure with the email address; never logs the password.
    # Does not say which of the two was wrong.
    address = email.strip().lower()
    record = await get_staff_store().find_by_email(address)
    stored = record.password_hash if record else _PLACEHOLDER_HASH
    if not check_password(password, stored) or record is None:
        log.warning("sign-in failed for %s", address)
        return None
    return Staff(id=record.id, email=record.email, role=record.role)

import hashlib
import hmac
import logging
import time
from fastapi import Cookie, Depends, HTTPException
from app.db.stores import get_staff_store

from app.settings import settings

TOKEN_HOURS = 8
log = logging.getLogger("user_notices.auth")


def _sign(payload: str) -> str:
    return hmac.new(settings.session_secret.encode(), payload.encode(), hashlib.sha256).hexdigest()


def issue_token(staff_id: int) -> str:
    # Return a signed session token for staff_id that expires in TOKEN_HOURS.
    # Depends on: settings.session_secret.
    expires = int(time.time()) + TOKEN_HOURS * 3600
    payload = f"{staff_id}.{expires}"
    return f"{payload}.{_sign(payload)}"


async def current_user(session: str | None = Cookie(default=None),
                       staff=Depends(get_staff_store)) -> Staff:
    # Return the signed-in staff member from the session cookie.
    # Received through Depends by every route except sign-in.
    # Depends on: staff, a StaffStore.
    # Raises HTTPException 401 for a missing, altered or expired token, or for
    # an account that no longer exists.
    parts = (session or "").split(".")
    if len(parts) != 3 or not (parts[0].isdigit() and parts[1].isdigit()):
        raise HTTPException(status_code=401, detail="Not signed in")
    staff_id, expires, signature = parts
    if not hmac.compare_digest(_sign(f"{staff_id}.{expires}"), signature):
        raise HTTPException(status_code=401, detail="Not signed in")
    if int(expires) < time.time():
        raise HTTPException(status_code=401, detail="Session expired")
    member = await staff.get_staff(int(staff_id))
    if member is None:
        raise HTTPException(status_code=401, detail="Not signed in")
    return member


async def require_editor(staff: Staff = Depends(current_user)) -> Staff:
    # Return the signed-in staff member if their role is editor.
    # Received through Depends by routes that change notices.
    # Raises HTTPException 403 for a viewer, and logs the denied request.
    if staff.role != "editor":
        log.warning("denied: staff %s has role %s", staff.id, staff.role)
        raise HTTPException(status_code=403, detail="Your role cannot do this")
    return staff

import logging
from datetime import datetime, timezone
from app.interfaces.notices import NoticeSummary
from app.interfaces.sms import SmsError

log = logging.getLogger("user_notices.notices")


class Notices:
    """Implements NoticeService from app/interfaces/notices.py."""

    def __init__(self, store, sms=None):
        self.store = store  # the notices store: a stub until Stage 7
        self.sms = sms      # the SMS client; only send_notice uses it

    async def schedule_notice(self, text: str, group_id: int,
                              send_at: datetime, author_id: int) -> NoticeSummary:
        # Store a notice with status "scheduled" for the group and send time.
        # send_at is a timezone-aware UTC datetime.
        # Depends on: self.store.
        # Raises ValueError for: empty text, an unknown group, a past send time,
        # a send_at with no time zone.
        # Does not send any messages; send_notice does that.
        if not text.strip():
            raise ValueError("Notice text is empty")
        if send_at.tzinfo is None:
            raise ValueError("send_at must include a time zone")
        if send_at <= datetime.now(timezone.utc):
            raise ValueError("Send time is in the past")
        if not await self.store.group_exists(group_id):
            raise ValueError(f"Unknown group {group_id}")
        return await self.store.add_notice(text, group_id, send_at, author_id)

    async def list_notices(self, limit: int = 50) -> list[NoticeSummary]:
        # Return up to limit notices, latest send time first.
        # Depends on: self.store.
        # Raises ValueError if limit is not between 1 and 200.
        if not 1 <= limit <= 200:
            raise ValueError("limit must be between 1 and 200")
        return await self.store.list_notices(limit)

    async def send_notice(self, notice_id: int) -> None:
        # Send the notice text by SMS to every opted-in user in its group.
        # Depends on: self.store, self.sms.
        # Sets status "sending" before the first message, then "sent", or
        # "failed" if any message failed. Records one message per recipient,
        # with the provider's message id when the provider accepted it.
        # Logs a failed message with the user id, never the phone number.
        # Raises LookupError for an unknown notice; ValueError if its status
        # is not "scheduled".
        # Runs inside the request until Stage 8 moves it to a worker.
        notice = await self.store.get_notice(notice_id)
        if notice is None:
            raise LookupError(f"Unknown notice {notice_id}")
        if notice.status != "scheduled":
            raise ValueError(f"Notice {notice_id} is {notice.status}, not scheduled")
        await self.store.set_status(notice_id, "sending")
        all_sent = True
        for recipient in await self.store.list_recipients(notice_id):
            try:
                message_id = await self.sms.send(recipient.phone, notice.text)
            except SmsError:
                log.warning("SMS failed: notice %s, user %s", notice_id, recipient.user_id)
                await self.store.record_message(notice_id, recipient.user_id, "failed", None)
                all_sent = False
            else:
                await self.store.record_message(notice_id, recipient.user_id, "sent", message_id)
        await self.store.set_status(notice_id, "sent" if all_sent else "failed")
